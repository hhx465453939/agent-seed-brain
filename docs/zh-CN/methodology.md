# 方法论文档 —— 算法原理与已知边界

> 这份文档解释四个机制**为什么这样设计**，以及它在什么情况下会失效。
> 不读它也能用；读了它，你才知道该在什么时候不信它。

---

## 0. 一个前提：为什么不引入语义检索

本项目坚持 **字符 n-gram + IDF**，而不是 embedding。三个理由：

1. **零依赖**：不需要模型、不需要网络、不需要 GPU。任意受限环境（内网、离线、CI）
   都能跑。
2. **可复现**：同一输入必得同一输出。embedding 模型一升级，历史排序全变，断言无法
   比对。
3. **可解释**：每次命中能列出 `(信号, 权重)`，用户能追问「为什么是它」。

代价也很明确：**同义改写不保证命中**（「冷峻」↔「冷漠」）。这是有意识的取舍，
见 §7。

---

## 1. 分词：2-gram 全权重，3-gram 降权

中文没有词边界。引入分词器就引入词典依赖，且分词结果随词典版本漂移。

所以用滑窗 n-gram：

```
「赛博霓虹」→ 2-gram: 赛博, 博霓, 霓虹    3-gram: 赛博霓, 博霓虹
```

- **2-gram 权重 1.0**：`霓虹` 能命中「赛博霓虹」「雨夜霓虹」「霓虹倒影」
- **3-gram 权重 0.35**：中文 3 字常跨词边界（「信息密度」→「息密」），只作确认信号

英文词单独提取并小写化；停用词（`style` / `的` / `ai` 等）剔除。

> `ai` 被特意列入停用词：任务里的「AI」指人工智能，而源库里的 `` `AI:` `` 是提示词
> 前缀。这条规则来自一次真实误判 ——「艾未未」因为名字里有 `Ai` 被错误召回。

## 2. IDF：让低频但精确的信号浮上来

```
idf(g) = log(1 + N / (1 + df(g)))
```

- `df=1`（罕见）→ 约 `log(1+N)`，N=200 时 ≈ 5.3
- `df=100`（常见）→ 约 `log(1+2)` ≈ 1.1

**3~5 倍的权重差**就是「无偏」的数学来源：它不靠随机打散，而是让稀有信号在匹配时
说话更响。

### 为什么 T4 拆成两个断言

早期版本只用端到端对照（开 IDF vs 关 IDF，看 top1 命中率）。
在小语料上实测两者都是 72.7% —— **不是算法坏了**，而是探针里的稀有词只属于目标
种子，关掉 IDF 时目标仍独享那 1 分。

端到端对照依赖「库里存在大量短文本 + 通用词」这一条件，小 fixture 造不出来。所以：

- **T4a（硬断言）**：IDF 单调性 —— `df` 越小 `idf` 越大。确定、不依赖库规模、
  能真失败。
- **T4b（不退化检查）**：端到端 top1 对照，只要求「开 IDF 不显著差于关 IDF」。
  大库上仍能抓到明显倒退。

## 3. 长度归一：温和，而不是惩罚

```
score = raw / (1 + log1p(grams) / 10)
```

早期用 `sqrt(grams)` 做归一，结果是**条目多的层整体被压死**，反而摧毁了「平等摊开」。

长文本信息量大，理应更容易相关；要防的只是「靠命中的 gram 数量堆分」。所以分母用
对数、且系数只有 1/10。

---

## 4. 跨层配额：先保底，再补满

`top-K` 不能纯按分数取，否则条目多的层（如 352 粒的章档）会把 12 粒的代码基因卡
全挤掉。

**两阶段分配**：

1. **保底**：每层先取 `min(floor(k×quota), 该层候选数)` 个（层内按分数）。
2. **补满**：按全局分数补到 K（某层无候选时，配额自然让给有货的层）。

`quota` 用 `floor(k×q)` 并做削峰，保证 `sum(quota) ≤ K` —— 否则保底名额会被最后
截断丢掉。

> 这个机制在开发期被自己的断言 T6a 抓出过一个真 bug：
> 旧实现只防「某层超配额」，却不保「某层有货却拿不到位」—— 按分数单次扫到底，
> 弱层候选常排在 K 之外，等于配了白配。

## 5. 时间衰减：多样性的唯一来源

```
recovery   = 1 - exp(-Δt / τ)          τ = 14 天
count_pen  = 1 / (1 + 0.5·ln(1+count))
novelty    = max(0.15, recovery × count_pen)
```

- 刚用过（Δt=0）→ `recovery=0`，但下限 `0.15` 保住「用户就想复现上次结果」的可能
- 14 天后 → `recovery≈0.63`
- 60 天后 → `recovery≈0.99`（再乘次数惩罚）

**刻意的选择：不用随机数。**

随机能带来多样性，但带来的是「不合适但不同」；衰减带来的才是「同等合适但不同」。
同一任务隔几天再跑，你会看到候选自然轮换；同一天连跑两次，结果稳定。

> 下限作用在**最终值**上，而不是只作用在 `recovery` 上。
> 早期写成 `max(0.15, recovery) × count_pen`，刚用过的种子会掉到 0.11 ——
> 复现能力形同虚设。

## 6. 增量：三条硬约束

| 约束 | 为什么 | 由谁守 |
|---|---|---|
| **已有 ID 绝不改写** | 旧 ID 一改，风味日志、状态记忆、外部引用全部断链 | T12 |
| **增量结果 ≡ 全量重建** | 不等价就是索引在骗人 | T10（split-half） |
| **`ref` 必须存在且不越界** | 猜错的路径会变成静默断链 | T1c + `Profile.resolve` |

增量池（`additions.jsonl`）独立于源文件，理由：

- 源库是**人工策展产物**，脚本盲插会破坏分层与格式约束
- 增量池可审计、可回滚、可批量审阅后再回填
- 回填后删除那一行，`build` 结果不变（幂等）

### 查重为什么用包含度而不是 Jaccard

新种子通常只有名字 + 几个信号（短），已有卡片文本很长。Jaccard 的并集分母会把
相似度稀释到 0.05，**查重永远不告警**。

```
包含度 = |A ∩ B| / min(|A|, |B|)
```

它回答的是「这粒是不是已有那粒的别名」—— 这才是查重要问的问题。

## 7. 已知边界（什么时候不该信它）

| 边界 | 表现 | 建议 |
|---|---|---|
| **不是语义检索** | 同义改写（「冷峻」↔「冷漠」）不保证命中 | 在 `signals` 里补充常见说法；或等后续的向量后端（见 roadmap） |
| **2-gram 跨词** | 「条件数」会切出「件数」 | 计分无害（idf 仍指向正确簇），展示层已去冗余 |
| **小语料上 IDF 无力** | <30 粒时，稀有词几乎都是独有的 | T4b 只要求「不退化」；想看真实区分度需要足够大的库 |
| **数量级** | 全库扫描，O(N) 每次 | 1e4 粒以内单次 <500ms；更大需索引加速（v0.4） |
| **状态是本地的** | 多机 / 多 agent 不同步 | 用日粒度而非次粒度可缓解；跨机共享需外部状态存储 |

## 8. 一条设计纪律

**断言必须能失败。**

开发期被自己的断言抓出过三个问题：

1. 配额只有上限没有下限 → 弱层被饿死
2. novelty 下限乘完次数惩罚掉到 0.11 → 复现失效
3. 旧货架样本里引用了三个不存在的 id → 下游「去中心化」断言恒真（永远 PASS）

第 3 条最危险：**一个永远绿的测试，比没有测试更坏**。所以 `verify` 有 T1d
「旧货架样本有效」专门检查测试自己。

---

## 9. 一句话总结它买到了什么

合适性由 IDF 决定 —— 确定、可解释、可复现。
多样性由状态记忆产生 —— 同一任务隔几天再跑，会拿到不同的**同等合适**候选，
而不是随机的**不合适**候选。
