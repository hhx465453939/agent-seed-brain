## 2. 债务明细

| # | 债务 | 代价 | 严重度 |
|---|---|---|---|
| D1 | 两份脚本靠 md5 手工对齐 | 改一个 bug 要同步两处；漏一次就静默分叉 | 高 |
| D2 | `PROFILES` 硬编码 | 新领域必须改 Python，违背「配置驱动」 | 高 |
| D3 | 验证套件不可作为库调用 | `sys.path.insert` 相对导入；无法在第三方项目里复用 27 项断言 | 中 |
| D4 | 无包结构 | 无法 `pip install`；只能 `git clone` + 路径调用 | 中 |
| D5 | 无公开 API | 使用者只能调 CLI，无法嵌入自己的 harness | 中 |
| D6 | 无版本导出 | 脚本里 `__version__ = "0.1.0"` 无发布语义 | 低 |
| D7 | `check_counts.py` 与 `seed_brain*.py` 风格/报告类不统一 | 两套 `Report` 实现，输出格式不一致 | 低 |

## 3. 许可风险（最高优先）

| 资产 | 许可 | 风险 |

## 4. 已有能力基线（改造后必须逐项不回退）

| 能力 | 当前证据 |

**共 38 项断言**（美学 27 + 数学 11）。SDK 化后必须能对任意领域复现同等强度的验证。

## 5. 技术风险

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| TOML 不可用 | Python 3.9/3.10 无 `tomllib` | 配置用 JSON（C3） |
| 正则外置后错配 | profile 里的 `entry_re` 写错 | `build` 时校验「解析出的条目数 > 0」，否则报错而非静默出空索引 |
| 外部 root 路径穿越 | `--root` 指到仓库外 | 只读操作；`ref` 必须落在 root 内，越界则拒绝 |
| 上游回填失败 | SDK 版本与上游期望不符 | 迁移前先冻结上游 commit，逐项比对 38 项断言 |
| 抽象过度 | 为「未来可能的领域」加无用配置项 | 只把**已经在两个领域验证过**的差异外置；未验证的一律不进 schema |
